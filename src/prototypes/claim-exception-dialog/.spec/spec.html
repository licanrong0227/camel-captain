认领异常弹窗

本文档是用户与 Agent 围绕当前原型进行方案沟通和持续生成的事实依据。只维护当前有效方案，并简短记录会影响当前原型的重要用户决策。

当前方案

  • 原型意图：把「认领异常」从一整段接口原文 JSON 串改成逐商品的异常清单，让用户能直接看出是哪些商品、因为什么原因认领失败，并就地进入编辑。
  • 使用场景：认领中心批量认领商品，点击「自动编辑」后部分商品校验不通过，弹出「认领异常」弹窗。
  • 当前表达：页面只保留「认领异常」弹窗本身，挂在灰遮罩上视口居中；弹窗内每个失败商品一行，包含图片、标题、父SKU 与类目、异常原因和「编辑商品信息」按钮。

事实与输入

用户确认事实

  • 原型名称：认领异常弹窗。
  • 弹窗中需要列出：商品图片、标题、错误信息，并提供操作项「编辑商品信息」。
  • 现状问题（来自截图）：弹窗只展示 {"allocate_40846":"请至少添加一个SKU", ...} 这样的接口原文，用户无法对应到具体商品。
  • 设计基底：camel-captain-erp。
  • 异常内容：混合多种异常，不只「请至少添加一个 SKU」。
  • 「编辑商品信息」本轮只做按钮样式与悬停/按下态，不接跳转。
  • 只呈现认领异常弹窗：认领中心页面、认领商品弹窗等弹窗以外的内容不保留。

当前假设

  • 弹窗宽度 660px，异常列表最多展示约 5 行，超出部分列表内滚动，头部汇总与底部按钮固定。
  • 底部沿用现状图的单个「确定」按钮居中排列，不改成右下角双按钮。
  • 页面为独立弹窗页：只保留灰遮罩与弹窗，弹窗固定打开，右上角 × 与「确定」保留视觉、不接关闭逻辑。
  • 错误文案统一写成「原因 + 修正动作」，例如「未读取到商品 SKU，请至少添加一个 SKU」。
  • 演示 12 个失败商品，覆盖 6 种异常，图片与标题取自项目已有商品素材，标题与图片题材保持一致。

原型范围

本次呈现

  • 认领异常弹窗：汇总说明、12 条商品异常明细（图片 + 标题 + 父SKU + 类目 + 异常原因）、逐条「编辑商品信息」、底部「确定」。
  • 灰遮罩背景，弹窗视口居中，列表内滚动。

本次不呈现

  • 认领中心页面、认领商品弹窗等背景内容（已按用户要求移除）。
  • 「编辑商品信息」的真实跳转与编辑页承载。
  • 按异常类型筛选、批量修正、批量重新认领、异常导出。
  • 真实接口数据、分页、加载与失败重试。

设计基底与原型特有调整

  • 采用的 DESIGN.md：src/themes/camel-captain-erp/DESIGN.md
  • 继承方式：默认严格遵循（品牌色、功能色、中性色、字号行高、按钮与表格规范、遮罩量级、阴影两档）。
  • 本原型特有调整：异常弹窗底部沿用现状图的单个「确定」居中按钮；异常原因用 danger-1 浅底 + danger-5 文本的块状呈现，以便逐条区分多异常。

当前待确认事项

  • 异常条数较多时是否需要「全部去编辑」或「按异常类型分组」入口（本轮未做）。
  • 「编辑商品信息」后续是跳转现有编辑产品弹窗，还是打开独立编辑页。
