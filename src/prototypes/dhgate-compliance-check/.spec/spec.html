敦煌网商品合规检测原型

本文档是用户与 Agent 围绕当前原型进行方案沟通、确认和持续生成的事实依据。只维护当前有效方案，并简短记录会影响当前原型的重要用户决策和变更。

当前方案

  • 原型意图：在骆驼队长 ERP 内嵌页面中演示「输入敦煌网商品链接 → 后台并行质检 → 独立结果反馈」的完整合规检测体验。
  • 使用场景：运营/商家/审核/质检管理员发起检测、查看记录与结果、点赞点踩反馈。
  • 当前表达：单原型多页面路由（发起检测 / 质检记录 / 质检详情 / 规则说明），核心卖点「后台运行、刷新不丢失、并行返回」做成动态轮询演示；数据全部为前端模拟数据。

事实与输入

用户确认事实

  • 需求来源：《敦煌网商品合规检测 PRD（前端原型版）》（用户附件 前端原型绘制PRD.MD），页面清单 P1–P7、状态定义、质检项展示规范、验收标准以该 PRD 为准。
  • 质检规则依据：《商品合规检测规则说明》2026-10-13 更新版（用户附件）；规则说明只描述各质检项校验什么，不描述不校验的内容。
  • AI 识别结果展示约定（2026-10-14 批注）：凡涉及 AI 识别或图片文字识别的参考信息与违规/疑似原因，只呈现识别结论（发现/更匹配/无法判读等），不展示置信度、相似度、匹配度等模型内部数值——实际调用 AI 时不一定能获取这些数值。
  • 图库展示约定（2026-10-14 批注；同日按用户澄清调整）：比对到图片类图库（品牌 logo 图库、赌博机对比图片库）时，参考信息需展示库内样本图片；禁售/限售没有图片库，按规则库比对，展示对应规则条目（禁售：什么地区禁售什么产品；限售：什么地区销售什么产品需要什么资质）；纯文字词库/规则库/网址库仍以文本列出。
  • 设计基底：src/themes/camel-captain-erp/DESIGN.md（用户 2026-10-12 确认）。
  • 原型形态：单原型 + 顶栏导航多页面路由，不拆分为多个原型。
  • 演示方式：动态轮询演示——提交后进入详情页，各质检项约 15–30 秒内陆续从排队中→检测中→完成；任务状态存 localStorage，刷新页面不丢失。
  • 结果卡片视觉：色条 + 浅色底强调违规（详见「设计基底与原型特有调整」）。

  • 项目已有原型（如 my-products-bi）的商品缩略图素材与 ERP 页面骨架习惯：复用风格，不跨原型引用文件。

当前假设

  • 敦煌网链接合法域名按 dhgate.com 及其子域识别，商品详情链接形如 https://www.dhgate.com/product/...。
  • 质检子项共 6 个：材质检测、尺码检测、知识产权侵权风险检查、类目错放检查、价格违规检查、违法违规检查（PRD 4 核心流程）。
  • 商品主图、详情图等图片素材使用项目已有素材或 AI 生成白底商品图，不接入真实敦煌数据。

原型范围

本次呈现

  • P1 合规检测发起页：链接输入、校验错误提示、开始检测/清空（输入框右侧，清空仅有内容时显示）、最近检测列表（超过 5 条时「查看更多>>」跳质检记录）、重复提交提示。
  • P2 质检记录列表页：筛选栏（状态/时间/结果/搜索）、任务表格、任务状态标签、质检概览计数（通过/违规/疑似/失败）、查看/复制操作、分页。
  • P3 质检详情页：商品摘要卡、总体结论条、质检项结果卡片列表；检测中（动态轮询、骨架屏、已完成项可先看）与检测完成两种形态。
  • P4 质检项结果卡片：6 个质检项的违规/疑似/通过/检测失败状态展示，含违规/疑似原因、参考信息（匹配词高亮、原图标注、图片文字识别结果、对比表差异高亮）、建议方案、展开详情。
  • P5 忽略确认弹窗：已整体移除（2026-10-13 用户批注：没有忽略场景了，忽略状态、忽略操作与相关文案全部去掉）。
  • P6 满意度反馈弹窗：点赞可取消；点踩弹出原因标签（误报/漏报/原因不准/建议不准/参考信息缺失/其他）+ 文本；补充说明从空白变为非空时默认选中「其他」；卡片上已标记的原因按弹窗选项顺序展示，不按点击顺序。
  • P7 规则说明页：质检规则摘要与入口。
  • 异常状态：非敦煌链接、草稿/无效商品、采集失败（可重试）、单项检测失败（单项重试）、图片加载失败占位。

本次不呈现

  • 后端质检算法、敦煌接口调用、真实商品数据抓取。
  • 人工审核后台、词库/图库/规则库维护界面。
  • 真实轮询/WebSocket（用本地定时器模拟）。
