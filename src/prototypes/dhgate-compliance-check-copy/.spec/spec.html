敦煌网商品合规检测原型

本文档是用户与 Agent 围绕当前原型进行方案沟通、确认和持续生成的事实依据。只维护当前有效方案，并简短记录会影响当前原型的重要用户决策和变更。

当前方案

  • 原型意图：在骆驼队长 ERP 内嵌页面中演示「输入敦煌网商品链接 → 后台并行质检 → 独立结果反馈」的完整合规检测体验。
  • 使用场景：运营/商家/审核/质检管理员发起检测、查看记录与结果、点赞点踩反馈。
  • 当前表达：单原型多页面路由（发起检测 / 质检记录 / 质检详情 / 规则说明），核心卖点「后台运行、刷新不丢失、并行返回」做成动态轮询演示；数据全部为前端模拟数据。
  • 详情页双视图（2026-10-26）：默认「按商品信息维度查看」平铺展示采集到的商品资料（标题 / 主图 / SKU 图 / 价格 / 尺码表 / 属性 / 详情图文），问题直接标在对应信息上，点击标记打开右侧问题抽屉，一次看到该位置的全部问题；「按检测项维度查看」视图保留原有逐项结果与单项重试。两个视图共用同一份问题数据，数量口径一致。

事实与输入

用户确认事实

  • 需求来源：《敦煌网商品合规检测 PRD（前端原型版）》（用户附件 前端原型绘制PRD.MD），页面清单 P1–P7、状态定义、质检项展示规范、验收标准以该 PRD 为准。
  • 质检规则依据：《商品合规检测规则说明》2026-10-13 更新版（用户附件）；规则说明只描述各质检项校验什么，不描述不校验的内容。
  • AI 识别结果展示约定（2026-10-14 批注）：凡涉及 AI 识别或图片文字识别的参考信息与违规/疑似原因，只呈现识别结论（发现/更匹配/无法判读等），不展示置信度、相似度、匹配度等模型内部数值——实际调用 AI 时不一定能获取这些数值。
  • 图库展示约定（2026-10-14 批注；同日按用户澄清调整）：比对到图片类图库（品牌 logo 图库、赌博机对比图片库）时，参考信息需展示库内样本图片；禁售/限售没有图片库，按规则库比对，展示对应规则条目（禁售：什么地区禁售什么产品；限售：什么地区销售什么产品需要什么资质）；纯文字词库/规则库/网址库仍以文本列出。
  • 设计基底：src/themes/camel-captain-erp/DESIGN.md（用户 2026-10-12 确认）。
  • 原型形态：单原型 + 顶栏导航多页面路由，不拆分为多个原型。
  • 演示方式：动态轮询演示——提交后进入详情页，各质检项约 15–30 秒内陆续从排队中→检测中→完成；任务状态存 localStorage，刷新页面不丢失。
  • 结果卡片视觉：色条 + 浅色底强调违规（详见「设计基底与原型特有调整」）。

当前假设

  • 敦煌网链接合法域名按 dhgate.com 及其子域识别，商品详情链接形如 https://www.dhgate.com/product/...。
  • 质检子项共 6 个：材质检测、尺码检测、知识产权侵权风险检查、类目错放检查、价格违规检查、违法违规检查（PRD 4 核心流程）。
  • 商品主图、详情图等图片素材使用项目已有素材或 AI 生成白底商品图，不接入真实敦煌数据。

原型范围

本次呈现

  • P1 合规检测发起页：链接输入（支持完整商品链接或纯 itemCode，itemCode 自动补全为商品链接；输入框内右侧「粘贴」一键读剪贴板、有内容时显示清空）、校验错误提示、开始检测、点数消耗说明、最近检测列表（超过 5 条时「查看更多>>」跳质检记录）、重复提交提示。
  • P2 质检记录列表页：筛选栏（状态/时间/结果/搜索）、任务表格、任务状态标签、质检概览（全部通过 / 共 N 处问题）、查看/复制操作、分页。
  • P3 质检详情页：商品摘要卡、总体结论条、质检项结果卡片列表；检测中（动态轮询、骨架屏、已完成项可先看）与检测完成两种形态。2026-10-26 起默认进入「按商品信息维度查看」视图：单行结论条 + 视图页签 + 平铺的商品信息（整品风险横条 + 基本信息/主图/SKU 图/价格/尺码表/属性/详情图文）+ 位置标记 + 右侧问题抽屉 + 悬浮问题导航；「按检测项维度查看」视图保留原 6 张结果卡片。详情页顶部不再单独显示商品标题与状态标签，商品标题在商品信息视图的「基本信息」里展示，状态由结论条文字体现；整品风险横条只在「按商品信息维度查看」页签内、内容最上方显示。2026-10-27 起，全部演示场景集中在箱包模板记录（Vintage Quilted Chain Bucket Bag）这一条详情页上：通过标注面板的「整页演示场景」预设与 8 个商品信息模块、6 个检测项的场景控件切换查看，不用再跳到其他商品；其余 4 条记录仍按各自的真实结果展示。
  • P4 质检项结果卡片：6 个质检项的违规/疑似/通过/检测失败状态展示，含违规/疑似原因、参考信息（匹配词高亮、原图标注、图片文字识别结果、对比表差异高亮）、建议方案、展开详情。
  • P5 忽略确认弹窗：已整体移除（2026-10-13 用户批注：没有忽略场景了，忽略状态、忽略操作与相关文案全部去掉）。
  • P6 满意度反馈弹窗：反馈对象是一条检测结果，点赞可取消；点踩弹出原因标签（误报/漏报/原因不准/建议不准/参考信息缺失/其他）+ 文本；补充说明从空白变为非空时默认选中「其他」；结果上已标记的原因按弹窗选项顺序展示，不按点击顺序。
  • P7 规则说明页：按现有产品不做调整，页面只保留一行默认文字「按照现有产品，暂无需调整」，原 6 个质检项的规则内容在代码中注释保留。
  • 异常状态：非敦煌链接、草稿/无效商品、采集失败（可重试）、单项检测失败（单项重试）、图片加载失败占位。

本次不呈现

  • 后端质检算法、敦煌接口调用、真实商品数据抓取。
  • 人工审核后台、词库/图库/规则库维护界面。
  • 真实轮询/WebSocket（用本地定时器模拟）。

商品信息视图规范

详情页默认视图。把后台采集到的商品资料按 ERP 商品资料结构平铺（不压缩图片），问题直接标在出问题的文字、图片或表格行上；点击标记打开右侧问题抽屉，一次看到该位置的全部问题。本视图只读，不能就地修改商品信息，也不提供按元素重新检测。

视图关系

  • 页签两个：「按商品信息维度查看」（默认）与「按检测项维度查看」。切换写进 URL（view=product|items），可深链直达；检测项深链用 focus=<检测项> 自动展开对应卡片。
  • 同一份问题数据的两种投影：检测项视图按检测项汇总（一张图违反多项会在多个检测项里各出现一次）；商品视图按位置汇总（同一位置的多项问题合成一个标记，点开看全部）。
  • 数量口径一致：商品视图各标记数字之和 = 各检测项卡片「N 处违规/疑似/失败」之和 = 抽屉分组内的条目数。
  • 重试仍只在检测项视图：系统按检测项执行检测，不能对单个元素单独重检。

质检项展示规范

依据 PRD 8.1–8.6，每个质检项卡片的展开区内容。违规必展示：违规原因 + 参考信息 + 建议方案。一次检测可同时出现违规与疑似违规记录，每条记录按自身类型标注「违规」或「疑似违规」（左侧色条同步为该类型颜色），并在类型标题前加圆形序号徽标（与规则说明页同款 .dcc-item-no）；序号按卡片内全部记录连续编号，违规与疑似违规不各自重新起号；单条记录可收起。反馈跟着检测结果走：每条违规/疑似结果都是一张条目卡片，👍 / 👎 在这张条目卡片右上角、与「收起」并排，只有一条结果的卡片同样如此；通过态没有违规条目、检测失败未产生结果，这两种卡片都不提供反馈，只保留「重新检测」。 同一个检测项检测过多次时，卡片标题下方出现「检测记录」切换条：每个按钮是一次检测，显示第 N 次 + 检测完成时间（月-日 时:分），最近一次带「最新」，正在检测时写排队中/检测中；默认看最新一轮。切到历史记录后，状态标签、结论、违规/疑似条目、参考信息与建议都换成那一轮，右侧提示「历史记录，仅查看」，不显示点赞/点踩与「重新检测」；单项重新检测开始时，当前这一轮自动归档，完成后新结果成为「最新」。检测记录按检测项各自独立，商品信息视图、结论条与问题抽屉不随卡片切换变化。
