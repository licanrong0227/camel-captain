敦煌网商品合规检测原型

本文档是用户与 Agent 围绕当前原型进行方案沟通、确认和持续生成的事实依据。只维护当前有效方案，并简短记录会影响当前原型的重要用户决策和变更。

当前方案

  • 原型意图：在骆驼队长 ERP 内嵌页面中演示「输入敦煌网商品链接 → 后台并行质检 → 独立结果反馈」的完整合规检测体验。
  • 使用场景：运营/商家/审核/质检管理员发起检测、查看记录与结果、对检测结果反馈「检测不准」或补报漏报。
  • 当前表达：单原型多页面路由（发起检测 / 质检记录 / 质检详情 / 规则说明），核心卖点「后台运行、刷新不丢失、并行返回」做成动态轮询演示；数据全部为前端模拟数据。
  • 详情页结构（2026-10-31 重构）：左侧商品信息、右侧检测项左右分栏。检测项是唯一的聚合维度：一条命中记录 = 一条问题，归属一个检测项，带一个位置；位置只用于定位，不作为计数单位。右栏按「违规 → 疑似 → 建议自查 → 检测失败 → 通过」排序，通过项折叠为一行（全部通过时默认展开，避免右栏留白）；默认只展开第一个问题项。左栏的问题文字片段、图片、表格行/单元格高亮，点击高亮内容或定位点即可在右栏展开对应检测项、定位到该条记录与说明，并从该位置圆点向每条命中记录的圆点画连线；右栏条目的等级标签（文字前带同色圆点）点击则回到左栏对应圆点脉冲高亮，并连回该条目。整品级规则只作为「商品整体」位置展示，不再单独聚合「整品风险」。
  • 发起检测（2026-10-31 调整）：提交后不直接进入商品详情页，而是在发起页原位出现「本次检测」摘要卡，逐项返回 6 个检测项结果；完成后从卡片进入详情页。

事实与输入

用户确认事实

  • 需求来源：《敦煌网商品合规检测 PRD（前端原型版）》（用户附件 前端原型绘制PRD.MD），页面清单 P1–P7、状态定义、质检项展示规范、验收标准以该 PRD 为准。
  • 质检规则依据：《商品合规检测规则说明》2026-10-13 更新版（用户附件）；规则说明只描述各质检项校验什么，不描述不校验的内容。
  • AI 识别结果展示约定（2026-10-14 批注）：凡涉及 AI 识别或图片文字识别的参考信息与违规/疑似原因，只呈现识别结论（发现/更匹配/无法判读等），不展示置信度、相似度、匹配度等模型内部数值——实际调用 AI 时不一定能获取这些数值。
  • 图库展示约定（2026-10-14 批注；同日按用户澄清调整）：比对到图片类图库（品牌 logo 图库、赌博机对比图片库）时，参考信息需展示库内样本图片；禁售/限售没有图片库，按规则库比对，展示对应规则条目（禁售：什么地区禁售什么产品；限售：什么地区销售什么产品需要什么资质）；纯文字词库/规则库/网址库仍以文本列出。
  • 设计基底：src/themes/camel-captain-erp/DESIGN.md（用户 2026-10-12 确认）。
  • 原型形态：单原型 + 顶栏导航多页面路由，不拆分为多个原型。
  • 演示方式：动态轮询演示——提交后在发起页显示「本次检测」摘要卡，各质检项约 15–30 秒内陆续从排队中→检测中→完成；任务状态存 localStorage，刷新页面不丢失。
  • 结果视觉：四色语义——违规红、疑似违规橙、建议自查蓝、检测失败灰；通过绿。违规内容用浅色底 + 左侧色条 + 等级标签共同表达，不只依赖颜色。

当前假设

  • 敦煌网链接合法域名按 dhgate.com 及其子域识别，商品详情链接形如 https://www.dhgate.com/product/...。
  • 质检子项共 6 个：材质检测、尺码检测、知识产权侵权风险检查、类目错放检查、价格违规检查、违法违规检查（PRD 4 核心流程）。
  • 商品主图、详情图等图片素材使用项目已有素材或 AI 生成白底商品图，不接入真实敦煌数据。

原型范围

本次呈现

  • P1 合规检测发起页：链接输入（支持完整商品链接或纯 itemCode，itemCode 自动补全为商品链接；输入框内右侧「粘贴」一键读剪贴板、有内容时显示清空）、校验错误提示、开始检测（按钮内右侧问号悬停/聚焦显示点数消耗说明）、最近检测列表（超过 5 条时「查看更多>>」跳质检记录）、重复提交提示；提交后不跳页，在输入卡下方出现「本次检测」摘要卡，用结果色顶部色条、同色头部底与描边、外阴影与上下卡片区分；提交后先展示采集阶段（待采集/采集中、正在采集商品信息、6 项排队中），采集完成后逐项返回 6 个检测项结果，检测中可点「查看检测进度」；选择演示场景时打开带 live=1 的详情页，按真实完成顺序逐项揭晓同一场景，完成后可进入详情页，当前任务从最近检测中临时去重；原型演示中摘要卡默认使用「部分违规+失败」场景（3 通过 / 1 处违规 / 1 处疑似 / 1 项检测失败），可通过标注面板切换跟随真实结果/全部通过/多处违规/采集失败，选择具体场景后从卡片进入的详情带同一 preset；采集失败演示态不提供查看详情入口，但卡片内提供链接输入与「重新采集」；重试后回到采集阶段继续演示。
  • P2 质检记录列表页：筛选栏（状态/时间/结果/搜索）、任务表格、任务状态标签、质检概览（全部通过 / N 处违规 · N 处疑似 · N 项建议自查 · N 项检测失败，四段分别着色）、查看/复制操作、分页。
  • P3 质检详情页：左右分栏——左侧商品信息（商品整体 / 基本信息 / 主图 / SKU 图 / 价格 / 尺码表 / 商品属性 / 详情描述），问题位置高亮且可点击；右侧检测项列表（按严重度排序、通过项折叠、默认展开第一个问题项）、条目的位置/等级/原因/建议/检测不准；原图与原文不重复展示，直接看左侧商品信息。顶部结论条按结果给出结构化计数与四色底色；重新检测后的变化摘要附在结论右侧。2026-10-27 起，全部演示场景集中在箱包模板记录（Vintage Quilted Chain Bucket Bag）这一条详情页上：通过标注面板的「整页演示场景」预设与 8 个商品信息模块、6 个检测项的场景控件切换查看；其余 4 条记录仍按各自的真实结果展示。
  • P4 检测项结果：6 个检测项卡片（名称、状态、计数、右上角圆形箭头展开/收起；重新检测放在展开后的检测记录行右侧）；违规/疑似/建议自查条目按位置逐个展示，只保留原因（关键词高亮）、建议方案（可复制常值）与底部「检测不准？」；原图/原文由左侧商品信息直接展示，条目不再重复；参考信息（规则库、完整 OCR、图库样本）随结果保存但不展示；检测失败只显示失败原因、可重新检测，不提供反馈。
  • P5 忽略确认弹窗：已整体移除（2026-10-13 用户批注：没有忽略场景了，忽略状态、忽略操作与相关文案全部去掉）。
  • P6 检测结果反馈弹窗：反馈对象是一条检测结果或一个通过项。问题条目底部「检测不准？」；通过项展开后「检测结果有问题？」报漏报，默认预选「漏报」。理由为 误报/漏报/原因不准/建议不准/其他（无「参考信息缺失」），可补充说明；提交后就地显示「已反馈」并支持取消。
  • P7 规则说明页：按现有产品不做调整，页面只保留一行默认文字「按照现有产品，暂无需调整」，原 6 个质检项的规则内容在代码中注释保留。
  • 异常状态：非敦煌链接、草稿/无效商品、采集失败（可重试）、单项检测失败（单项重试）、图片加载失败占位。

本次不呈现

  • 后端质检算法、敦煌接口调用、真实商品数据抓取。
  • 人工审核后台、词库/图库/规则库维护界面。
  • 真实轮询/WebSocket（用本地定时器模拟）。

商品信息与检测项分栏规范

详情页左侧展示采集到的商品资料，右侧展示 6 个检测项。检测项是唯一的聚合维度：一条命中记录 = 一条问题，归属一个检测项，带一个位置；位置只用于定位，不作为计数单位。左栏只读，不提供编辑或按元素重新检测。

计数口径

  • 一条命中记录 = 一条问题。同一张图片命中知识产权与违法违规，算 2 条，分属两个检测项；图上只显示「2 处」，不合并成新的整品风险条目。
  • 同一张图片在同一检测项里命中两条规则，也算 2 条；同一段文字命中多条规则同理。
  • 位置只用于定位。商品整体也是位置之一：禁售、限售、赌博引导等规则本身作用于整品时，锚点写「商品整体」，与标题、主图、详情图并列展示，不再单独聚合「整品风险」。
  • 四档分开统计：违规 / 疑似违规 / 建议自查 / 检测失败。检测失败不计入违规与疑似；建议自查不计入疑似。
  • 结论优先级：违规 > 疑似 > 建议自查 > 检测失败 > 通过。结论条、右栏检测项卡片、质检记录页概览与发起页摘要卡使用同一批命中记录计数；左栏文本/表格区块标题显示该位置的「N 处问题」或「N 项检测失败」，媒体区块显示有问题的图片张数，图片上的多条问题由右侧条目逐条展示。

  • 检测失败：与违规条目一样呈现为一张小卡片，头部是带灰色圆点的「检测失败」小标签，下方显示失败原因与提示；连线连到该小标签（灰色虚线），点击标签或卡片正文即可展开卡片并与左栏失败位置双向定位。卡片提供重新检测，不提供反馈。通过项折叠在「检测通过 N 项」中（全部通过时默认展开），展开后可报漏报。

检测中、重新检测与采集

  • 检测中：左栏展示已采集的商品信息，右栏对应检测项显示排队/检测中骨架，不展示半成品条目；结果逐项返回后填充。
  • 就地重新检测：完成后结论条右侧显示「本次重新检测：X 处已修复 · Y 处仍存在 · Z 处新增」，仅当前页面会话保留。
  • 采集 loading 只显示加载占位卡；采集失败显示失败卡（失败原因 + 修改链接 + 重新采集），不展示分栏与结论条。

检测项展示规范

右侧检测项列表按「违规 → 疑似 → 建议自查 → 检测失败 → 通过」排序，通过项折叠。每条命中记录单独展示为一张条目，只保留原因、位置与建议；原图/原文不重复展示，参考信息也不展示。反馈跟着结果走：问题条目底部「检测不准？」，通过项展开后「检测结果有问题？」报漏报；检测失败不提供反馈；历史轮次只读。

卡片结构

  • 头部：检测项名称 + 状态标签 + 重新检测 + 右上角圆形箭头按钮（无文字）。多项计数（仅非失败且多于 1 条时显示）放在标题下方单独一行，展开时显示，收起时与检测记录一起折叠隐藏；折叠态只显示标题、状态标签与操作。
  • 条目：等级标签（标签内文字前带同色圆点，点击即关联商品信息）；卡片底部为「检测不准？」椭圆按钮；不重复检测项名称与位置标签。原因（关键词高亮）；建议方案（可复制常值）；原图/原文不重复展示。
  • 选中态：被左栏点中的关联条目改为透明底色（保留左侧等级色条）、不改变边框色，只给当前点中的条目加柔和投影；同一位置多条都会选中，从右栏单条记录发起时只投影该条目，未点中的不投影、不加边框；从商品信息发起时同位置的关联条目都投影；条目随结果滚动到可视区；点击条目正文同样定位并连线，条目内按钮不受影响。
  • 检测记录：同一检测项多次检测且卡片展开时显示检测记录下拉，不单独放「检测记录」标题（第一项为当前一轮，完成后带「最新」，检测中写排队中/检测中；历史项按时间倒序显示第 N 次 + 时间）。没有检测记录时不显示下拉，同一行左侧显示「当前为最新检测结果」占位文字，右侧为重新检测；有记录时下拉触发器弱化为 24px 高的小号灰字，默认无边框与底色，悬停或聚焦时才出现边框；展开为自定义菜单（白底、圆角、投影、选项悬停浅灰底、当前项品牌蓝底并带 ✓，不使用浏览器原生 select），历史提示同为 11px；历史轮次不可定位、不可重新检测，但保留「检测不准？」反馈入口，反馈按轮次独立保存；切到历史时断开当前连线并清除定位/选中高亮（历史记录可能命中不同位置）。
  • 检测失败：显示失败原因，提供重新检测；不提供检测不准反馈，不计入违规/疑似。
  • 通过项：折叠进「检测通过 N 项」；展开后每行显示名称 + 绿色「通过」标签（与上方状态标签同款），并提供「检测结果有问题？」入口，默认预选「漏报」。
  • 参考信息（规则库、完整图片文字识别结果、图库比对样本）随结果保存但不渲染，用于检测不准时的排查；前端只展示原因与建议；原图/原文看左侧商品信息。

四色语义

  • 违规红：需要修改，阻断发布；疑似违规橙：需要人工确认，不直接阻断；建议自查蓝：限售规则召回，系统不判定违规，只提示自查；检测失败灰：检测失败，结果不完整，可重试。
  • 通过绿只用于通过状态；颜色同时配合文字标签、左侧色条与图标，不只依赖颜色表达。

反馈规则

  • 问题条目：点卡片底部「检测不准？」打开反馈弹窗，理由是 误报 / 漏报 / 原因不准 / 建议不准 / 其他，可补充说明；提交后在按钮下方显示「已反馈：原因（说明）」与「取消反馈」，内容多时换行、取消反馈固定在右侧，可取消。
  • 通过项：展开通过分组后点「检测结果有问题？」打开同一弹窗，默认预选「漏报」。
  • 反馈不改变检测结果；检测失败不提供反馈；历史轮次不显示反馈入口。
