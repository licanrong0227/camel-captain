广告看板（报表 / 广告）主规格

设计基底：src/themes/camel-captain-erp/DESIGN.md（品牌橙 #FF7D29、中性色阶、1px 边框、8px 卡片圆角、表格白底浅灰表头）。系统位置：顶部导航「报表」下拉 → 新增「广告」板块 → 「广告看板」；面包屑「报表 / 广告 / 广告看板」。原型只有一个页面 #page=ad-report，三个视图用页面内页签切换。

1. 背景与范围

  • 数据来自敦煌广告的两份报表：商品报表（商品 × 计划 × 广告组 × 日期，含曝光、点击、消费、订单数、GMV）与 订单报表（一笔订单里的一个商品行，含订单号、成单词、GMV）。两份都缺对方的能力，必须拼。
  • 本期只做「看」：展示、筛选、排序、下钻。不做计划创建/出价/预算调整，不做导出，不做权限，不接真实接口。
  • 不做：分国家/分站点、分时段（数据源无这两个维度）；跨自然月自动切片（日期上限 31 天，超出直接拦截）。

2. 页面结构

  1. 顶部导航：报表为激活态；下拉分三组——订单（订单明细报表）、店铺（店铺看板）、广告（广告看板，本次新增并高亮）。前两组在本原型中只作位置说明，不可点。
  2. 筛选条：店铺、广告类型、日期（近 7 天 / 近 30 天 / 自定义 + 起止日期）、重置（紧跟筛选条件）、同步数据（右侧）；筛选即改即生效，不设查询按钮。下方一行说明数据更新时点与币种。
  3. 指标概览：4 张主卡（花费、GMV、订单数、ROAS）+ 6 个次级指标（曝光、点击、点击率、点击单价、转化率、客单价），全部带环比。
  4. 趋势：单指标可切换（花费 / GMV / 订单数 / 点击量 / ROAS），只展示每日实线。
  5. 明细区：三个页签（商品 / 计划 / 成单词）+ 异常图例 + 一行视图说明 + 表格 + 底部分页。明细区单独占一屏高度，首屏是筛选、指标卡和趋势，向下滚动查看完整列表（10 条/页可整屏显示）。
  6. 商品抽屉：点商品行从右侧打开，含按天走势、按计划拆分、带单成单词。

3. 指标口径

  • 以商品报表为准：花费、曝光、点击、订单数、GMV 全部来自商品报表，因此 ROAS = GMV ÷ 花费 等派生指标自洽。订单报表只用于成单词视图与订单明细。
  • 派生指标：点击率 = 点击 ÷ 曝光；点击单价 = 花费 ÷ 点击；转化率 = 订单 ÷ 点击；单均花费 = 花费 ÷ 订单；客单价 = GMV ÷ 订单；ROAS = GMV ÷ 花费。分母为 0 一律显示「-」，不显示 0 或 ∞。
  • 环比：与当前区间等长且紧邻的前一段对比；前一段早于数据起始日时不展示百分比，显示「-」。
  • 合计行：商品/计划视图对全部筛选结果求和（行之间互斥，不重复）；成单词视图按订单号与商品去重后再合计，不能行相加。
  • 成单词：按「店铺 + 成单词」分组，订单数 = 去重订单号数量，涉及商品数 = 去重成交商品数，GMV = 行 GMV 之和，最近成单日 = 最大日期。空单词归入「无搜索词（自动广告）」。
  • 异常：ROAS < 1 且花费 > 0 标红；花费 > 0 且订单 = 0 打「零转化」标签。
  • 时间：数据按 T+1 更新，演示数据截至 2026-10-19；区间上限 31 天。

3.1 数据链路（同步 → 本地库 → 报表）

  • 页面只读本地库：所有统计、排序、分页都在本地库上完成，打开页面或切换筛选都不请求平台接口，因此是即时出数。
  • 本地库两张表：商品维度表（nickname、itemcode、adType、planName、groupName、dateline + imp、click、usdCost、orders、gmv）与订单维度表（order_no、searchword、itemcode、order_itemcode、order_product_name、gmv、dateline）。商品视图、计划视图、指标卡、趋势取前者；成单词视图与订单明细取后者。
  • 同步任务负责入仓：按时间切片（单次接口上限 31 天，跨月按自然月切开）+ 分页把两份报表的明细全部拉回；日常由定时任务每天 T+1 跑一次，并回补最近 7 天覆盖归因回刷。
  • 手动同步按钮：筛选条右上角，用于手动补一次同步；同步中显示进度状态，完成后更新「最近同步」时间与写入行数，不改变查询条件。
  • 待确认（阻塞同步实现）：接口把 6 个业务参数全部标成必填（含 page、limit、adType），但「广告类型」描述写着「空：所有广告」，说明必填标记不区分能否传空。商品 ID 能否传空、传空是否返回全部商品需联调确认：若可为空，同步量只取决于「月数 × 页数」；若必须逐个传，则为「商品数 × 月数 × 页数」，500 在投商品时每天上千次请求，必须限流重试、只拉在投商品。
  • 行数量级 ≈ 商品数 × 计划数 × 广告组数 × 天数（100 商品 × 3 计划 × 30 天接近 1 万行）。

4. 字段与三视图列

视图行粒度列
商品视图 店铺 + 商品（跨广告类型合并） 店铺（全部店铺时出现）、商品（主图 + 名称 + 商品 ID）、广告类型（多个标签）、流量组（曝光 / 点击 / 点击率 / 点击单价）、转化组（订单数 / 转化率 / 单均花费）、收入组（广告花费 / GMV / ROAS）
计划视图 店铺 + 广告类型 + 计划 + 广告组 店铺（全部店铺时出现）、广告类型、计划、广告组 + 同上三组指标。全店自动广告的计划与广告组显示「-」，商品自动的广告组显示「-」
成单词视图 店铺 + 成单词 店铺（全部店铺时出现）、成单词、来源广告类型、订单数、GMV、涉及商品数、最近成单日、订单明细（展开）。不出现曝光/点击/花费，因为订单数据里没有这些指标

商品名称与主图由本地商品库按商品 ID 关联，缺失主图显示虚线占位；接口本身只给商品 ID。

列级取值：维度列——店铺 = nickname、商品 = itemcode、广告类型 = adType、计划 = planName、广告组 = groupName、成单词 = searchword、最近成单日 = dateline 取最大；指标列——曝光/点击/订单/花费/GMV 对明细同名字段求和（Σ imp / Σ click / Σ orders / Σ usdCost / Σ gmv），再在合计值上相除得到点击率、点击单价、转化率、单均花费、客单价、ROAS；成单词视图的订单数按 order_no 去重、涉及商品数按 order_itemcode 去重、最近成单日取最大 dateline。

4.1 字段对照（页面 → 接口 → 加工）

页面位置取数接口用到的字段 / 参数页面上的处理
日期筛选 两个接口 入参 datelineFrom / datelineTo 页面区间直接作为入参，≤ 31 天；接口只接受自然日，无小时粒度
广告类型筛选 两个接口 入参 adType 「全部」传空字符串；ppc 手动 / prodauto 商品自动 / shopauto 全店自动
店铺筛选 不进参数 返回行 nickname 接口没有店铺参数，拉回后按 nickname 本地过滤；全部店铺即各店明细直接相加
商品筛选 - 入参 itemcode 页面不提供单商品筛选，不传；文档标为必填，能否传空需联调确认
指标卡 商品维度 imp / click / usdCost / orders / gmv 先按当前筛选加总，再算比率（CTR、CPC、CVR、CPA、客单价、ROAS），不是逐行比率求平均
趋势 商品维度 dateline + 上述字段 按 dateline 分组求和；区间内缺失日期补 0；只展示每日实线
商品视图 商品维度 按 nickname + itemcode 分组 跨 adType、计划、广告组、日期合并；商品名/主图按 itemcode 关联本地商品库
计划视图 商品维度 按 nickname + adType + planName + groupName 分组 空 planName / groupName 显示「-」；无计划 ID，同名计划会合并
成单词视图 订单维度 searchword / order_no / order_itemcode / order_product_name / gmv / dateline 按 nickname + 词分组；订单数去重 order_no；涉及商品数去重 order_itemcode；最近成单日取最大 dateline；空词归「无搜索词」
异常标记 商品维度 gmv / usdCost / orders ROAS = Σgmv ÷ ΣusdCost < 1 且订单 > 0 → 标红；消费 > 0 且订单 = 0 → 零转化标签
商品抽屉 两个接口 nickname + itemcode 过滤后重算 趋势与计划拆分取商品维度，成单词取订单维度，三段都只统计当前商品与当前区间

5. 交互与状态

  • 筛选改动即时生效，无需点查询（本地计算，没有加载等待）；日期不合法时就地提示，页面数据保持上一次有效结果；「重置」恢复全部店铺、全部广告类型、近 7 天；「同步数据」点击后进入同步中状态（约 1.2 秒），完成后更新筛选条下方的「最近同步」时间与写入行数，查询条件和列表数据不变。
  • 日期校验就地提示：起止不完整、结束早于开始、超出 31 天、早于数据起始日或晚于数据截止日都会拦住查询。
  • 页签切换保留筛选条件，重置页码与展开行，商品/计划默认按花费降序、成单词默认按 GMV 降序。
  • 点任一指标列切换排序（降序 ⇄ 升序）；合计行固定在表格底部，随横向滚动对齐。
  • 表格内部滚动、表头两级吸顶、分页固定在卡片底部（10 / 20 / 50 / 100 条每页）；顶部导航与面包屑吸顶，不随页面滚动。
  • 点商品行打开右侧抽屉（带遮罩），Esc 或关闭按钮收起；抽屉内容只统计当前商品与当前筛选区间。
  • 成单词行可展开订单明细，只展示金额最高的 6 笔。
  • 空态保留表头并提示可清空筛选；趋势全 0 时显示「所选区间暂无数据」。

6. 假设与待确认

  • GMV 与消费均按美元展示；如店铺存在多币种，需确认汇率取值方式。
  • 数据更新时点按 T+1 假设，真实延迟需与数据侧确认。
  • 报表合计与广告后台展示可能有小差异（归因与退款处理不同），界面上不做补偿。
  • 计划与广告组只有名称、没有编号，同名计划会被合并，改名后历史会断开。
  • 演示数据：3 家店铺、12 个商品、2026-08-19 至 2026-10-19 共 62 天；预置锚点包括一个 ROAS 约 0.7 的商品、一个 10 月起有花费无订单的商品、一个只投全店自动广告的商品、一笔含两个商品的订单。
